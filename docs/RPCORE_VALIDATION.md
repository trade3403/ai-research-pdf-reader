# RPCore 测试、性能与安全验收
状态：待建立测试基线；以下指标为建议目标，不是测试结果。

## 样本集
合成最小 PDF（每个操作符及异常条件）；合法可分发的 SCI 单栏/双栏论文、中文、数学公式、表格、矢量图、嵌入字体、旋转页、不同 CropBox、扫描页、加密页、对象流、增量更新、损坏文件。记录来源、许可证、SHA-256、预期能力及人工标注；未经授权的论文不提交公开仓库。将测试工具与生产依赖隔离。

## 质量门槛
- 解析：对象及页树单测、xref/对象流/增量更新回归；未知能力返回明确错误。
- 渲染：固定 DPI、背景、字体环境；与参考引擎及人工审查比较，记录像素差/SSIM 和文本遗漏，逐类设定容差；不把抗锯齿差异直接视为错误。
- 文字：人工标注集测 Unicode 字符错误率、阅读顺序和选区覆盖；建议基础文本字符准确率 >=99%、受控双栏阅读顺序 >=95%，复杂样本单列报告；坐标往返误差目标 <=1 屏幕像素（测试缩放和旋转）。
- 科研：区域检测 precision/recall、表格结构、公式结构及置信度；保留原始页码、选区、人工纠正入口。
- 性能：在同一 Windows x64 设备、相同样本和渲染 DPI 下，记录冷/热首屏、翻页、缩放、搜索 P50/P95、峰值 RSS、缓存命中率。先建立 PDF.js 基线，再设定量化优化目标；不编造提速比例。
- 交互：连续滚动、跨行跨页划词、双栏、批注、缩放旋转、关闭文档、取消任务、异常恢复；用真实应用回归测试 ChatGPT/Word/文献库/翻译/数据库。
- 发布：cargo fmt/check/test/clippy、依赖审计、模糊测试、Windows 安装包和离线启动测试；保留构建锁文件、样本报告及已知限制。

## 安全要求
PDF 视为不可信输入。限制文件大小、对象数量、递归深度、引用环、流解压大小及比例、图片像素、页面尺寸、渲染时间与缓存预算；使用 checked arithmetic 和边界检查，优先安全 Rust。模糊测试 lexer/xref/stream/content/font，禁止无限循环和无界分配。禁止 PDF JavaScript、自动执行附件或外部命令；网络访问默认关闭。链接外部打开须用户确认；密码不写日志。仅允许经授权的本地路径；使用不透明文档句柄限制 IPC，远程 ChatGPT WebView 不得访问核心接口。生产环境考虑独立受限解析进程，崩溃不影响应用。任何 unsafe/FFI 需独立审查。

## 数据和发布策略
原始 PDF 默认只读。旧批注及文献指纹保持兼容，迁移前备份；数据库恢复做完整性验证。引擎切换通过 feature flag，可退回原阅读器；未达门槛不删除旧引擎。最终发布包检查无 PDF.js、PDFium、MuPDF 运行时依赖。报告每项指标的样本数量、设备、版本、失败清单与实际结果。
