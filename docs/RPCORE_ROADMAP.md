# RPCore：自主 Rust PDF 核心研发路线
状态：规划，尚未实现。基线：应用 V0.5.9。核心版本独立于应用版本。

## 目标与边界
以 ISO 32000 为依据，自主实现 PDF 文件解析、内容解释、页面对象模型、文字坐标、渲染调度、选择、搜索及科研布局分析。不在交付产品中依赖 PDFium、MuPDF、PDF.js 或其他完整 PDF 引擎。允许通用 Rust 解压、字体、几何、光栅化、图像库；逐项审计许可证及锁定版本。PDFium 等仅可作为隔离的测试参考，不链接进交付物。参考公开标准及论文独立实现；记录来源、许可证、算法决策，不宣称已取得专利或完全兼容标准。
现有 Tauri/React、文献库、ChatGPT、翻译、Word、SQLite 保留；过渡期 PDF.js 仅作现有应用备用，RPCore 本身不依赖它。最终移除须通过验收。

## 阶段与交付门槛
| 核心版本 | 研发内容 | 验收与交付 |
|---|---|---|
| 0.1 | 字节词法、对象、字典、数组、间接引用、xref 表/流、对象流、增量更新、页面树、Flate 等流解码 | 合成及真实合法样本解析；页数、页面盒、资源继承正确；错误文件返回结构化错误；CLI dump；无 panic |
| 0.2 | 内容操作符、图形状态栈、CTM、路径、裁剪、颜色、字体与字形、图片、透明度 | 基础文本/矢量/图像页输出 PNG；与参考图比较；未支持功能显式报告，不静默丢失 |
| 0.3 | 字符索引、ToUnicode/CMap、字形四边形、文本行、命中测试、跨行选择、搜索、批注坐标 | 旋转/缩放/CropBox 坐标往返；双栏选择及高亮一致；复制原文可溯源；搜索取消 |
| 0.4 | 科研版面、阅读顺序、标题摘要、图注、表格、公式、引用段落 | 标注集评估阅读顺序、区域检测、表格结构和公式识别；置信度与人工纠正；保留页码及坐标 |
| 0.5 | 连续滚动、虚拟化、分块渲染、预加载、预算缓存、后台任务与取消 | Windows x64 实机对照 PDF.js；记录首屏、翻页、缩放、搜索、峰值内存；压力测试多文档及大文件 |
| 1.0 | 兼容性、安全、稳定 API、打包与迁移 | corpus 回归、模糊测试、依赖审计、Windows 安装与端到端回归全部通过；支持矩阵公开；无已知阻断性数据丢失或安全缺陷 |

应用 V0.6.x 可开始实验接入，不承诺 RPCore 1.0 的发布日期。每阶段独立提交和评审，未通过门槛不得默认切换引擎。

## 执行顺序
1. 在 feature/rpcore-bootstrap 建立独立 Rust workspace、CI、样本生成器及 CLI，不改现有阅读器。
2. 先做 parser/decoder/document 的最小闭环，再做显示列表和渲染；禁止用完整 PDF 库替代核心实现。
3. 统一字符与图形坐标，再做选择、搜索和标注；最后做科研语义层。
4. 通过 feature flag 接入 Tauri，默认保留现有引擎；验证旧批注和文献关联兼容。
5. 通过回归门槛后才删除 PDF.js 及其资源复制流程；保留可回滚的稳定版本。
