# D1.2 自主 Tokenizer

## D1.2a — Unigram 核心
参考 [SentencePiece 论文](https://arxiv.org/abs/1808.06226)、[模型规范](https://github.com/google/sentencepiece/blob/master/src/sentencepiece_model.proto)、[归一化规范](https://github.com/google/sentencepiece/blob/master/doc/normalization.md)。目标模型候选 [Helsinki-NLP/opus-mt-en-zh 固定仓库版本](https://huggingface.co/Helsinki-NLP/opus-mt-en-zh/tree/7b05ad2cd70ad11863b0fffc3327c13a26ab4f8a) 提供 source.spm、target.spm 和 vocab.json；真实二进制文件未能取得，未确认其内部具体 normalizer、piece 类型及完整词表。

独立 Rust Viterbi 动态规划：以 UTF-8 字符边界构建候选路径，累加 log score，回溯最优 token 序列；缺失单字符时增加 UNK 路径（最小正常 score -10）；相邻 UNK 合并。仅支持 NORMAL、UNKNOWN、CONTROL；输入 TSV（id/type/score/piece），不直接解析 protobuf。Identity profile：ASCII 空格合并、dummy prefix、U+2581 空格标记；不是完整 Unicode NFKC。控制符跳过，未知 token 默认表面文本。显式限制 vocab 16 MiB、200000 piece、单 piece 128 bytes、输入 64 KiB、有限 score。使用 f64 累分；同分和长文本精度与原实现尚待进一步对照。

## 对照测试
在研发环境实际运行 Python sentencepiece 0.2.1，手工构建合成 ModelProto，取得 11 组 normalization、token ID、decode 参考结果（英中、空白、数字、重音、Greek、emoji、UNK、制表符、换行）。fixture 和重建脚本位于 crates/rpmodel/tests；CI 仅 Rust，不需要 Python 或下载模型。另有非法词表、越界、特殊 token、全局路径优于贪心测试。不是实际 OPUS-MT 翻译结果。

## D1.2b — 必须完成后才验收整阶段
取得固定版本真实模型文件并记录来源/许可/哈希；自主解析 SentencePiece ModelProto 与 normalizer 配置，支持目标模型实际算法及必要字符映射；适配源/目标词表、Marian vocab.json ID 映射与 EOS/PAD/UNK；真实英中输入与 reference token IDs、解码一致性报告。若目标实际采用 BPE 或其他模型类型，需要额外实现。D1.2a 不应直接当作 Marian 可用 tokenizer；本阶段不包含神经翻译。

## D1.2b1 — 二进制模型与 ID 映射
新增有界 protobuf wire reader（varint、fixed32、fixed64、length-delimited；拒绝截断、溢出、非法 wire），解析 ModelProto 词表、score、piece type、trainer 特殊 ID、normalizer 和 charsmap。16 MiB / 200000 piece 上限。只执行已经支持的 identity Unigram profile，其他归一化、BPE、byte fallback 等明确返回 Unsupported；解析成功不等于可执行。Marian ID 映射目前接受独立提供的词表映射，缺词回退显式 UNK；JSON 文件解析、语言前缀、EOS 策略和目标解码待续。
合成二进制 fixture 由本地 Python SentencePiece 0.2.1 ModelProto.SerializeToString 真实生成，8 个 piece（<unk>, <s>, </s>, <pad>, ▁, 学, a, ▁学），参考 "学 a" → [7,4,6] → "学 a"。Rust 测试直接解析文件，无 Python 运行依赖。
模型卡标注 Apache-2.0，并要求目标语言标记。固定候选 revision 7b05ad2cd70ad11863b0fffc3327c13a26ab4f8a；当前开发环境 DNS 无法访问 Hugging Face，使用单独 CI probe（仅 D1.2b1 提交触发） 尝试下载三个分词文件（不下载模型权重），记录 SHA256 与 SPM 元数据。仅探测，不是完整分词验收。探测失败时整体 workflow 失败，CPU job 仍独立记录。不得把 probe 失败视为通过。后续根据真实 normalizer 实现 compiled charsmap、Marian JSON 和 token ID 精确对照。

## D1.2b2a — compiled charsmap
参考 SentencePiece normalizer 格式（[公开实现与格式](https://sources.debian.org/src/sentencepiece/0.1.97-3/src/normalizer.cc)）：4 字节 LE trie 长度、32 位 double-array units、NUL 结尾替换池。自主安全 Rust 最长前缀查找，检查访问范围、UTF-8、leaf、输入输出及前缀长度。默认 dummy prefix/trim/escape profile；未支持 user-defined symbol 优先匹配、其他 normalizer flags 或原文坐标映射；暂不接入真实 Unigram 推理。Runner 固定模型文件哈希并用 Python SentencePiece 0.2.1 作测试对照（不进入 Rust 发布包），每个源/目标模型 19 个归一化样本，结果以日志为准。
