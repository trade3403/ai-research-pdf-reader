# D1.10c — Scientific glossary

Status: implementation submitted; CI pending.

- Seed glossary: 69 project-authored candidate aliases, not an authoritative terminology standard. Domain selection is explicit: general, geotechnical, biology. Common terms are inherited; contradictory common/domain keys and same-scope normalized keys are rejected, even in inactive scopes. Different domain-specific meanings are allowed. Identical normalized duplicates are deduplicated.
- Bounded TSV input, UTF-8 byte offsets, Rust BTreeMap trie. ASCII case fold, horizontal whitespace collapse, three hyphen variants; explicit plural aliases only, no stemming, no matching across newline. Longest complete alias at a word boundary; hyphen is a delimiter, not automatic semantic context. Formula/quantity/chemical/symbol precedence at scan position is unchanged. No claims about arbitrary notation or contextual disambiguation.
- API Glossary::from_tsv and TextSession::translate_glossary; CLI: `rptranslate translate-glossary-int8 MODEL_DIR geotechnical "We measured maximum strain." 1 64`. Legacy exact caller glossary and plain/number-only translation remain unchanged. Custom TSV via Rust API, not CLI file import in this stage.
- Tests: normalized conflict, domain separation, UTF-8 boundaries, longest phrase, variants, reserved input, literal precedence, no term sent to model, real FP32/INT8 fixed independent expectations and eight paper sample segments. Fixed term restoration is not sentence quality: fragmented gaps may hallucinate, omit, reorder or duplicate scientific content. Explicit rejection, no default switch. No training; no automatic domain classification. Next D1.10d only after full CI and user instruction.
