# Electron V0.6.0 migration bootstrap
Separate preview app: existing Tauri and React sources are untouched. This is not a feature-complete replacement. A strict ChatGPT origin allowlist intentionally blocks auth redirects; use external browser until a reviewed auth flow is implemented. No local data is exposed to the remote view. No PDF content is loaded yet.
Run: cd electron-preview; npm install; npm test; npm start. Build: npm run dist.
Initial dependency ranges must be resolved and lockfile committed before release; CI currently uses npm install for bootstrap. Next: React/Vite integration, platform adapter, authenticated navigation tests, SQLite/credential migration, RPCore worker integration, installation smoke tests.

## 0.6.1 migration slice
Build root React using npm install and npm run build, then in electron-preview run npm install, npm run workspace and npm start. Default window now loads the actual existing React build via a restricted studio:// protocol. --shell-preview retains the original isolated test shell. React uses existing browser fallback storage and HTML file input, not native SQLite. ChatGPT in React remains fallback only; the earlier isolated view is available in shell-preview. No old data migration yet. PDF.js remains transitional. GUI evidence captures actual Electron renderer frames while opening a generated PDF; it is not full desktop video, not proof of other features or RPCore. Production release still requires lockfiles and real Windows validation.

## Chromium compatibility fix
GUI run 45322531691 showed a real page error: `this[#n].getOrInsertComputed is not a function`. Electron 39 was too old for the current PDF.js APIs. Pin Electron 44.11.5 (Chromium 152); retain sandbox/CSP and actual PDF rendering assertions, add runtime capability diagnostics. Revalidate on official Windows CI. This is a transitional PDF.js compatibility fix, not RPCore integration.

## V0.6.2 first slice
Native ChatGPT WebContentsView is connected to the React dock; bounds follow its CSS viewport in DIP (default zoom), hidden on drag and closed on unmount. Strict chatgpt.com navigation, external browser fallback, no privileged remote preload or auto-submit. Actual remote login is not validated. Native node:sqlite database stores reader documents and annotations using fixed operations; one-time transactional import of V0.6.1 reader localStorage, original keys retained, no arbitrary SQL IPC. Other stores remain browser fallback and V0.5.9 Tauri DB migration is not implemented. GUI smoke validates PDF rendering, native reader record and native child geometry/lifecycle; renderer video does not guarantee capture of the remote child pixels. Tests cover SQLite persistence and invalid inputs. PDF file paths/reopen, full library/Word/translation database migration and real login remain follow-up tasks.

### V0.6.2 second slice
User-selected PDF files are copied to a SHA-256 addressed private vault (100 MiB limit, verified on reopen). Only vault IDs can be read through IPC; no arbitrary filesystem reads. Reader restores up to four recent managed files after restart. Library metadata, collections and per-page substring search use a separate native SQLite database with transactional browser-preview migration. Original PDFs are not modified; deleting library entries does not delete vault files. Vault garbage collection, full backups and V0.5.9 migration remain pending. GUI regression adds real library import and process restart. PDF.js remains transitional.

## V0.6.3 first slice
Native SQLite stores research clips, editable Word JSON manuscripts, translation preferences/glossary/cache and local usage counters, with independent one-time transactional imports from browser preview storage. Original browser keys are retained. No arbitrary SQL IPC. Azure API keys and live online requests are deliberately not migrated in this slice; cached translations remain usable. Unit tests cover rollback, reopen, preserved creation date and atomic quota. GUI smoke extends to research clip and Word draft save. V0.5.9 Tauri database migration, complete backup and native export remain pending.

### V0.6.3 second slice
Azure Translator requests use fixed HTTPS endpoint from main process, bounded batches/time/response, no redirects or key exposure to remote page; Windows safeStorage (DPAPI) encrypted file with no plaintext fallback. Quota is reserved per submitted batch in main process, failed requests are conservatively counted. Actual paid/live Azure request requires user credentials and is not tested in CI; unit tests use injected transport. Word export uses native save dialog and atomic file write; existing Mammoth/docx libraries remain, no C-line algorithm work. GUI verifies actual DOCX roundtrip and dummy-key encryption; file dialog selection alone substituted for CI. Complex Word layout fidelity, complete backup, legacy Tauri migration remain pending.

## V0.6.4 first slice: verified backup
Native folder chooser creates a versioned backup directory with three SQLite VACUUM INTO snapshots and managed content-addressed PDFs. Manifest records SHA-256 and size, verifies expected DB tables, SQLite quick_check, PDF hashes and database references. Snapshots execute synchronously in the main process before asynchronous immutable PDF copies. Temporary directory is renamed only after verification. User can independently verify a chosen backup directory. No credential files, ChatGPT sessions, localStorage preferences, unsaved edits or external legacy attachments are copied; external references are counted. This is a full native-data snapshot, not incremental backup. Destructive restore and crash-safe rollback are deliberately deferred. GUI tests use substituted folder selection only, actual backup/verification and real DB/PDF files. Also fixes ambiguous translation settings test locator. No B/C line changes.

### V0.6.4 second slice: generation-based recovery
Restore copies the verified backup into a new private data generation, revalidates it, and stages an atomic pending marker. At restart before databases open, revalidate, preserve maximum monthly Azure usage, mark native imports complete, and atomically select the generation. Original data is retained as the previous generation (not overwritten or deleted); rollback is a separate confirmed restart operation. On validation failure before pointer commit keep original data selected and retain failure marker. Single-instance lock avoids competing main processes. No full power-loss durability proof; failed staging/old generations are retained for manual recovery and no automatic garbage collection. Credentials and browser preferences remain profile-level and are not restored. Legacy V0.5.9 migration and incremental backup remain pending. GUI tests verify two actual restarts, restored PDF and changed research note, rollback; unit test injects corrupt staged DB.

### V0.6.4 third slice
Incremental repository uses SHA-256 objects and per-snapshot manifests; unchanged objects are verified and reused, new objects are copied and verified before publishing a snapshot. Each database still receives a complete VACUUM snapshot (file-level, not SQLite page-level delta). Keep the whole repository; export a snapshot to the existing standalone backup format before restore. No automatic object garbage collection. V0.5.9 legacy preflight is read-only, checks known table/column names, counts records and external PDF references, refuses live WAL/journal. It does not import data, read referenced attachments, or migrate API credentials. Unit tests exercise reuse, damaged objects, export, legacy schema detection. GUI regression creates and exports an incremental snapshot. Actual legacy import remains a separate next slice.
